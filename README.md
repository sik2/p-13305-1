## MVC 패턴
MVC는 Model, View, Controller의 약자입니다. 하나의 애플리케이션을 구성할 때 구성요소를 세 가지 역할로 구분한 패턴입니다.

- **Model**: 애플리케이션의 데이터를 나타냅니다. DB, 상수, 변수 등 데이터와 정보들의 가공을 책임지는 컴포넌트입니다.
- **View**: 사용자 인터페이스 요소를 나타냅니다. 데이터를 기반으로 사용자들이 볼 수 있는 화면을 담당합니다.
- **Controller**: 데이터와 사용자 인터페이스를 잇는 다리 역할을 합니다. 사용자의 이벤트들을 처리하는 부분입니다.

## 스프링에서 의존성 주입(DI) 방법 3가지 방법

DI란 객체를 직접 생성하지 않고 스프링이 외부에서 넣어주는 것을 말합니다.

1. **생성자 주입**: 생성자를 통해 주입하는 방법으로 가장 권장되는 방식입니다. `@RequiredArgsConstructor`와 `final` 키워드를 사용합니다.
2. **Setter 주입**: Setter 메서드에 `@Autowired`를 붙여 주입하는 방법입니다.
3. **필드 주입**: 필드에 직접 `@Autowired`를 붙여 주입하는 방법입니다.

## JPA의 장점과 단점
- JPA(Java Persistence API)는 자바에서 관계형 데이터베이스를 객체지향적으로 다루기 위한 ORM(Object-Relational Mapping) 표준 명세입니다.

**장점**
- SQL을 직접 작성하지 않아도 되어 개발 속도가 빠릅니다. `articleRepository.findAll()` 처럼 메서드 호출만으로 DB 조회가 가능합니다.
- 객체 중심으로 개발할 수 있어 코드가 직관적입니다. Java 객체를 그대로 DB에 저장하고 불러올 수 있습니다.
- DB 종류가 바뀌어도 (MySQL → Oracle 등) 코드 수정이 거의 없습니다. JPA가 알아서 해당 DB에 맞는 SQL을 생성해줍니다.
- 기본적인 CRUD 기능을 자동으로 제공해줘서 반복적인 코드 작성을 줄일 수 있습니다.

**단점**
- 복잡한 쿼리(통계, 대용량 데이터 처리 등)는 JPA로 처리하기 어렵고 직접 SQL을 작성해야 할 때가 있습니다.
- 잘못 사용하면 불필요한 쿼리가 많이 발생해 성능이 떨어질 수 있습니다. (N+1 문제)
- 내부 동작 방식을 이해하지 못하면 예상치 못한 버그가 발생할 수 있어 학습 곡선이 있습니다.

## HTTP GET 요청과 POST 요청의 차이

**GET**
- 서버에서 데이터를 조회할 때 사용합니다.
- 전달하는 데이터가 URL에 노출됩니다. (예: `/article/detail?id=1`)
- URL에 데이터가 포함되므로 북마크나 공유가 가능합니다.
- 브라우저에 캐싱이 되어 같은 요청을 반복할 때 빠릅니다.
- 예) 게시글 목록 조회, 게시글 상세 조회

**POST**
- 서버에 데이터를 전송할 때 사용합니다.
- 데이터가 URL이 아닌 요청 Body에 담겨 전송되어 URL에 노출되지 않습니다.
- GET보다 보안에 유리하며 대용량 데이터 전송이 가능합니다.
- 예) 게시글 등록, 로그인
